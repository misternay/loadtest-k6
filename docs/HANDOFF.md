## 1. สิ่งที่ส่งมอบ

### 1.1 เว็บไซต์บทเรียน (พร้อมใช้งาน)

เว็บไซต์ **static 14 หน้า** ภาษาไทย สอนโหลดเทสต์ด้วย k6 ตั้งแต่คำนวณ TPS
ไปจนถึงอ่านผลลัพธ์และแก้ปัญหา ไม่มี build step ไม่มี dependency ของ Node
ไม่มี CDN ไม่มีฟอนต์ภายนอก — อัปโหลดโฟลเดอร์ `site/` แล้วใช้ได้ทันที

| หน้า | เนื้อหา |
|---|---|
| `index.html` | หน้าแรกและสารบัญบทเรียน |
| `lessons/01-tps.html` | คำนวณ TPS / RPS จากสูตรและจากผลจริง |
| `lessons/02-vu.html` | virtual user คืออะไร lifecycle และการเลือก executor |
| `lessons/03-metrics.html` | แคตตาล็อก metric ของ k6 และวิธีหาเวลาที่หายไป |
| `lessons/04-percentiles.html` | เปอร์เซ็นไทล์ p95 / p99 และการตั้ง threshold |
| `lessons/05-load-profiles.html` | รูปแบบการทดสอบ 6 แบบและโหลดโปรไฟล์ |
| `lessons/06-read-results.html` | อ่านผลลัพธ์ตามลำดับ และกับดักที่พบบ่อย |

สีหลัก `#1f4e79` รองรับความกว้าง 360 px ขึ้นไป ไม่มี overflow แนวนอน

### 1.2 สคริปต์ k6 5 แบบ (รันได้จริง)

ทุกตัวมีกลไกกันการยิงผิดปลายทาง (`ALLOWED_HOSTS`) และตรวจผ่านการรันจริง

### 1.3 ปลายทางจำลองสำหรับฝึก

`mock-server/server.mjs` — HTTP server ไม่ใช้ dependency ภายนอก
มี endpoint ให้ทดลอง 6 แบบ รวมถึงพารามิเตอร์ `?delay=N` สำหรับสร้าง
"ช่วงอุ่นเครื่องที่ช้า" แบบกำหนดได้

mock server มี **สองโหมดบทบาท** ที่แยกชัดเจน

| โหมด | เปิดอย่างไร | พฤติกรรม |
|---|---|---|
| ประพฤติดี (ค่าเริ่มต้น) | `node mock-server/server.mjs` | ตอบทุกคำขอในราว 6–46 ms ไม่มีหางยาว ใช้เป็นปลายทางอ้างอิงที่มั่นคงสำหรับชุดทดสอบทั้งหมด |
| หางยาว | `TAIL_RATE=0.03 node mock-server/server.mjs` | 3% ของคำขอช้าลง 150–570 ms ใช้สาธิตเปอร์เซ็นไทล์ในบทที่ 4 เท่านั้น |

`GET /health` รายงานค่า `tailRate` ปัจจุบันด้วย จึงตรวจได้ทันทีว่ากำลังรันโหมดใด

## 2. วิธีเข้าใช้งาน

### 2.1 เปิดเว็บในเครื่อง

```bash
cd loadtest-k6
node -e "const h=require('node:http'),f=require('node:fs'),p=require('node:path');h.createServer((q,s)=>{let u=decodeURIComponent(new URL(q.url,'http://x').pathname);let t=p.join('site',u==='/'?'index.html':u.slice(1));if(!f.existsSync(t)||f.statSync(t).isDirectory()){s.writeHead(404).end('404');return}const m={'.html':'text/html; charset=utf-8','.css':'text/css','.js':'text/javascript','.json':'application/json','.svg':'image/svg+xml'};s.writeHead(200,{'content-type':m[p.extname(t)]||'application/octet-stream'});s.end(f.readFileSync(t))}).listen(8000,()=>console.log('http://localhost:8000'))"
```

เปิด <http://localhost:8000>

**ห้ามเปิดด้วย `file://`** เพราะหน้า `tools/latency.html`, `lessons/03-metrics.html`
และ `glossary.html` ดึงข้อมูลด้วย `fetch()` จาก `assets/data/*.json`
เบราว์เซอร์จะบล็อกด้วยนโยบาย same-origin แล้วตารางและกราฟจะว่างเปล่า

### 2.2 รันสคริปต์ k6

```bash
# ต้องสตาร์ท mock server ก่อนเสมอ
node mock-server/server.mjs &

```

### 5.1 แก้แล้ว: เกณฑ์ของ `smoke.js` และ `load.js` เข้มเกินไปเมื่อเจอหางยาวของ mock server

**สถานะ: แก้โค้ดแล้ว รอผลการยืนยัน 30 ครั้ง** (ระหว่างเขียนเอกสารนี้ การรันซ้ำ 30 ครั้งยังไม่จบ

อาการเดิม: รัน `k6 run k6/smoke.js` แล้วได้ exit 99 โดยที่ระบบปลายทางไม่ได้มีปัญหา

สาเหตุเดิมมีสองข้อประกอบกัน

1. `vus: 1, duration: '10s'` และ `sleep(1)` ทำให้ได้เพียงราว 10 รอบ (30 ข้อตรวจ)

2. mock server เปิดหางยาว 3% (+150–570 ms) เป็นค่าเริ่มต้นตลอดเวลา

| ฝั่ง | แก้เป็น |

| mock server | หางยาวปิดเป็นค่าเริ่มต้น เปิดด้วย `TAIL_RATE=0.03` เมื่อต้องการสาธิตเท่านั้น |

### 5.2 แก้แล้ว: `delayAbortedCheck` ไม่มีอยู่จริงใน k6

## 5.8 แก้ล่าสุด: redesign โหมด refinement (ธีมสว่าง/มืด + เน้นส่วนสำคัญ + ตัดสำนวน)

รอบนี้เป็น **refinement** ของเว็บเดิม ไม่ใช่การทำใหม่ — โครงสร้าง ลิงก์ และตรรกะเดิมคงอยู่ทั้งหมด

### 5.8.1 สิ่งที่ทำ

**1) โหมดสว่าง/มืด**
- นิยามสีเป็น CSS variable 23 ตัว โดย `:root` = โหมดสว่าง และ `[data-theme=dark]` = โหมดมืด
  ประกาศโหมดมืดซ้ำอีกชุดใน `@media (prefers-color-scheme: dark)` เพื่อเป็นค่าตั้งต้นตามระบบ
  สำหรับผู้ใช้ที่ยังไม่เคยเลือก
- โหมดมืด **ออกแบบใหม่สำหรับพื้นเข้ม** ไม่ใช่กลับสี: พื้นหลัง `#11151b` (ไม่ใช่ดำสนิท),
  ตัวอักษร `#e4e8ee` (ไม่ใช่ขาวสนิท), ขอบเป็น `rgba(255,255,255,.08/.18)`
  และ `--accent` ถูกยกจาก `#1f4e79` เป็น `#8fbce9` เพื่อให้ลิงก์ผ่าน 4.5:1 บนพื้นเข้ม
  (วัดได้ 9.19:1 เทียบกับพื้นหลัง โหมดสว่างได้ 8.37:1)
- ปุ่มสลับธีมเป็น `<button>` จริงในท็อปบาร์ สร้างโดย `site.js` มี `aria-label` ภาษาไทย
  ที่บอกการกระทำ (“เปลี่ยนเป็นโหมดมืด”/“เปลี่ยนเป็นโหมดสว่าง”) ไอคอนเป็น inline SVG
  ดวงอาทิตย์/ดวงจันทร์ stroke 1.7 ขนาดเป้ากด 32×32 px และมีสถานะ hover/active/focus-visible ครบ
- จำค่าใน `localStorage` คีย์ `ltk6.theme.v1` และมีสคริปต์สั้น ๆ ใน `<head>` ของ **ทุกหน้า**
  วาง **ก่อนลิงก์ CSS** เพื่อตั้งธีมก่อนวาดครั้งแรก จึงไม่มีจอกะพริบขาว
- สีที่วาดด้วย JavaScript ทั้งหมดย้ายมาเป็นโทเคน: `charts.js` ไม่มี hex/rgb ฮาร์ดโค้ดเลย
  (สีกราฟ 25 จุดอ่านจาก CSS variable) และแก้สีตายตัวที่เหลือใน CSS
  (เงา hover ของตาราง, ขอบ callout, สี tooltip, พื้นหลัง backdrop) ให้เป็นโทเคน

**2) เน้นส่วนสำคัญ**
- ทุกบทเรียน (6 หน้า) และ `troubleshooting.html` มีบล็อก **“ใจความสำคัญ”** อยู่บนสุดของเนื้อหา
  กลั่นจากเนื้อหาจริงในหน้านั้น หน้าละ 3–5 ข้อ เป็นประโยคบอกสาระ ไม่ใช่คำโปรย
- เพิ่มคลาส `.keypoint` (บรรทัดที่สำคัญที่สุดของบท หน้าละ 1–2 จุด) และ `.key-figure`
  (ตัวเลข/สูตรที่ต้องจำ ล็อกความกว้างหลักด้วย `font-variant-numeric: tabular-nums`)
- เพิ่ม **แถบความคืบหน้าการอ่าน** ด้านบน (เลือกวิธีนี้แทนการเน้นหมายเลขบท เพราะช่วยกับบทที่ยาว)
  อ่านสีจาก `--accent` จึงเปลี่ยนตามธีม และไม่แสดงตอนพิมพ์
- วินัยของ accent: ไม่เพิ่มสีใหม่ การเน้นใช้ **น้ำหนักตัวอักษร + พื้นผิว + ระยะห่าง** เป็นหลัก
  บล็อกใจความสำคัญใช้เส้นคั่นบน-ล่าง **ไม่ใช้การ์ดมุมโค้ง + ขอบซ้ายสี** และไม่มีเงาฟู/gradient

**3) ตัดสำนวน**
- ลดคำในเนื้อความของ 7 หน้า (บทเรียน 6 + troubleshooting) จาก **16,501 → 12,064 คำ = 26.9%**

  คำอธิบายซ้ำสองที่ และย่อหน้าที่ไม่เพิ่มข้อมูลใหม่
- **ไม่เสียข้อเท็จจริงใด ๆ**: ตัวเลข สูตร ตาราง โค้ด และเกณฑ์ตัดสินคงเดิมทุกตัว

### 5.9.5 ข้อจำกัดที่ยังเหลือของรอบนี้

- **ทดสอบเฉพาะ Chromium 153.0.8010.12** — ยังไม่ได้ทดสอบ Safari และ Firefox
  (สไตล์สไลเดอร์มีทั้ง `::-webkit-slider-*` และ `::-moz-range-*` แต่ยังไม่ยืนยันบนเบราว์เซอร์จริง)
- **Chromium ปัดค่า range ที่ตั้งด้วยโปรแกรมให้ตรงกับ step** — ถ้าพิมพ์ 10.5 ลงช่องที่เป็นจำนวนเต็ม
  สไลเดอร์จะปัดเป็น 11 ขณะที่ช่องกรอกยังเป็น 10.5 และขึ้นข้อความเตือน "ต้องเป็นจำนวนเต็ม" ตามเดิม
  เป็นพฤติกรรมที่ตั้งใจ (ช่องกรอกเป็นตัวจริง สไลเดอร์เป็นการสำรวจ) แต่ยังไม่ยืนยันบนเบราว์เซอร์อื่น
