เหตุผลของหลักฐานชุดนี้
  เอกสารและบทเรียนเคยใช้ชื่อตัวเลือก delayAbortedCheck ซึ่งไม่มีอยู่ใน k6 v2.2.0
  หลักฐานชุดนี้ตอบสามคำถามด้วยการรันจริง ไม่ได้อ้างจากความจำ
    1) ตอนนี้สคริปต์ทั้ง 5 ไฟล์ยังทำให้ k6 เตือน unknown field อยู่ไหม
    2) delayAbortEval ตัดข้อมูลช่วงอุ่นเครื่องออกจากการคิด threshold หรือไม่
    3) ถ้าต้องการตัดสินเฉพาะช่วงภาวะคงตัวจริง ๆ ต้องทำอย่างไร


======================================================================
ส่วนที่ 1 — ตรวจว่าไม่มีคำเตือน unknown field อีกแล้ว
======================================================================

วิธีตรวจ: k6 inspect จะแยกวิเคราะห์ options ของสคริปต์และรายงานฟิลด์ที่ไม่รู้จัก
โดยไม่ต้องรันโหลดจริง (ตรวจแล้วว่าวิธีนี้จับได้จริง ดูข้อ 1.1)


$ for f in smoke load stress spike soak; do k6 inspect k6/$f.js; done   # สรุปจำนวนบรรทัดเตือน

k6 inspect k6/smoke.js  → จำนวนบรรทัดเตือน unknown field: 0   (exit 0)
k6 inspect k6/load.js  → จำนวนบรรทัดเตือน unknown field: 0   (exit 0)
k6 inspect k6/stress.js  → จำนวนบรรทัดเตือน unknown field: 0   (exit 0)
k6 inspect k6/spike.js  → จำนวนบรรทัดเตือน unknown field: 0   (exit 0)
k6 inspect k6/soak.js  → จำนวนบรรทัดเตือน unknown field: 0   (exit 0)

หมายเหตุ: k6 inspect เขียน JSON ของ options ที่แปลงแล้วออกทาง stdout
บรรทัดเตือน (ถ้ามี) ออกทาง stderr จึงกรองด้วย grep ได้ตามคำสั่งด้านล่าง

$ k6 inspect k6/load.js 2>&1 | grep -i 'unknown field'
(ไม่มีผลลัพธ์ = ไม่มีฟิลด์ที่ไม่รู้จัก)

$ k6 inspect k6/stress.js 2>&1 | grep -i 'unknown field'
(ไม่มีผลลัพธ์ = ไม่มีฟิลด์ที่ไม่รู้จัก)

======================================================================

การออกแบบการทดลอง
  สคริปต์: docs/evidence/probes/probe-delay-abort-eval.js
  ใช้ vus 1 นาน 20 วินาที โดย 10 วินาทีแรกยิงไปที่ /api/items?delay=600
  (ปลายทางตอบ 600 ms คงที่ = จำลองช่วงอุ่นเครื่อง) แล้วอีก 10 วินาทีที่เหลือ

    ก. ไม่มี abortOnFail, ไม่มี delayAbortEval
    ข. ไม่มี abortOnFail, มี delayAbortEval '12s'
    ค. มี abortOnFail,   ไม่มี delayAbortEval
    ง. มี abortOnFail,   มี delayAbortEval '12s'

export function steady() {
  http.get(`${BASE_URL}/api/items`, { tags: { scenario: 'steady' } });

ชื่อตัวเลือกที่ถูกต้องของ k6 v2.2.0

  • ชื่อ delayAbortedCheck ไม่มีอยู่จริง และ k6 ไม่ได้ทำงานตามที่เขียนไว้

สิ่งที่ delayAbortEval ทำ
  • เลื่อน "เวลาที่ k6 ใช้ตัดสินใจหยุดการรัน" เมื่อ threshold ที่ตั้ง abortOnFail: true ไม่ผ่าน
    หลักฐาน: กรณี ค ถูกตัดเมื่อรันได้ 02.0s กรณี ง ถูกตัดเมื่อรันได้ 12.0s

สิ่งที่ delayAbortEval ไม่ได้ทำ
  • ไม่ได้ตัดข้อมูลช่วงอุ่นเครื่องออกจากการคิดค่า threshold
    หลักฐาน: กรณี ก กับ ข รันจนจบ 20.1s กับ 20.1s
    และได้ p(95) 603.32 ms กับ 602.49 ms ซึ่งใกล้กันมาก

ผลข้างเคียงที่ต้องรู้ (พบจากการทดลองในโปรเจกต์นี้)
  • k6 ตรวจชื่อฟิลด์ที่ไม่รู้จักเฉพาะระดับบนสุดของ options
    ถ้าใส่ชื่อผิด "ข้างใน" ออบเจกต์ threshold k6 จะเงียบและเพิกเฉย ไม่มีบรรทัดเตือน
    ดังนั้นให้ตรวจด้วย k6 inspect ซึ่งแสดง options ที่แปลงแล้ว แทนการดูแค่ว่ามีบรรทัดเตือนไหม
